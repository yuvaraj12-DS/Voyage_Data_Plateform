# Source Data Mapping

The Hotel Booking Demand dataset is used as the historical
source for the simulated Voyage Booking System.

The source dataset is not copied directly into the operational
database. Selected fields are transformed into the operational
schema.

## Tenant and Property Mapping

The source dataset contains two hotel categories:

- Resort Hotel
- City Hotel

For this project, these are mapped to two synthetic businesses
and properties.

| Source hotel | Tenant | Property | Destination |
|---|---|---|---|
| Resort Hotel | TENANT001 / Mallorca Travel Co | PROP001 / Mallorca Resort Hotel | Mallorca |
| City Hotel | TENANT002 / Barcelona Travel Co | PROP002 / Barcelona City Hotel | Barcelona |

These tenant, property and destination values are synthetic and
are introduced for the project. They are not present in the
original dataset.

## Booking Mapping

| Source field | Operational field | Transformation |
|---|---|---|
| — | booking_id | Synthetic ID generated by loader |
| — | tenant_id | Derived from source hotel |
| — | property_id | Derived from source hotel |
| — | customer_id | Synthetic ID generated per booking |
| arrival_date_year | arrival_date | Combined with month and day |
| arrival_date_month | arrival_date | Combined with year and day |
| arrival_date_day_of_month | arrival_date | Combined with year and month |
| lead_time | booking_date | arrival_date minus lead_time |
| stays_in_weekend_nights | room_nights | Added to weekday nights |
| stays_in_week_nights | room_nights | Added to weekend nights |
| adults | adults | Direct mapping |
| children | children | Null values treated as 0 |
| adr | adr | Direct mapping |
| market_segment | market_segment | Direct mapping |
| is_canceled | status | Used with reservation_status |
| reservation_status | status | Used to derive operational status |
| reservation_status_date | updated_at | Used as the source update timestamp |

## Status Mapping

The operational booking status is derived as follows:

- is_canceled = 1 → CANCELLED
- reservation_status = Check-Out → COMPLETED
- otherwise → CONFIRMED

## Customer Mapping

The source dataset does not provide a suitable customer
identifier.

A synthetic customer_id is therefore generated for the source
system.

The source country and customer_type fields are retained.

## Source Data Quality Decisions

children contains a small number of missing values. These are
treated as zero because the field represents a count.

country may be missing and is therefore retained as NULL.

The source contains negative ADR data. Negative ADR values are
not loaded into the bookings table because the operational
schema requires ADR to be non-negative.

Invalid records are written to booking_rejections for traceability.

## Fields Not Currently Modeled

The following source fields are intentionally not included in
the first operational version:

agent
company
deposit_type
required_car_parking_spaces
total_of_special_requests
previous_cancellations
previous_bookings_not_canceled
days_in_waiting_list

These fields can be introduced later if required by the
analytics layer.

## Customer Identity Limitation

The public dataset does not contain a persistent customer identifier.

For the first source-system implementation, a synthetic customer_id
is therefore generated for each reservation.

This is sufficient for demonstrating source-system relationships
and API integration but does not support true customer-level
cross-booking behavior.

A future version may introduce a synthetic customer identity
generator when customer-level attribution becomes necessary.
